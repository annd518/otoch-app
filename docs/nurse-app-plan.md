## 4. Шинэ дараалал

Зарчим: 10-27-ны Go/No-Go хүртэл (**8 хоног**) **гар томилолт + зөвхөн админ бүртгэсэн сувилагч** бүхий туршилтын (pilot) хувилбарыг найдвартай болгоно. Автомат dispatch нь push-гүй бол бодит бус тул L1-д **унтраалттай** (`DISPATCH_INTERVAL_MS=0`), push бэлэн болсон хойно асаана. Хэмжээ: S ≤ ½ өдөр, M ≈ 1 өдөр, L ≥ 2 өдөр (миний хэмжилт, баталгаагүй).

### Үе A · Нэгтгэх, хамгаалах (S–M) · **өөрийн branch**
1. `origin/main`-г `feat/nurse-app` руу merge (1 конфликт). Тестийн 1 мөр. 196/196 баталгаажуулна. (Эзэмшигчийн зөвшөөрөл: merge + push.)
2. R2: `requireNurse` → идэвхгүй бол `401 ACCOUNT_DISABLED`; nurse-app-д тест.
3. R3: `admin.ts`-д `EN_ROUTE`, `INCIDENT`-ийг идэвхтэй гэж тооцох (**main-ийн файл**, `server/**` branch дээр, `admin.ts`-д хүрэхийг зөвшөөрнө үү).
4. R6: «Залгах» → «Яаралтай холбоо» шошго (эсвэл өвчтөний утасны талбар нэмэх шийдвэр).
5. R8: GitHub Actions: server тест (түр PostgreSQL), nurse-app typecheck/lint/test. Цагийн хамааралтай 11 тестийн шалтгааныг (цагийг mock хийж) олно.
- **Гарах шалгуур:** CI ногоон, merge-д конфликтгүй, R2/R3 тесттэй.

### Үе B · Админ тал (M–L) · **`wclient/**`-д хүрэх зөвшөөрөл хэрэгтэй**
1. R1: `POST /api/admin/staff` NURSE үүсгэхэд `NurseProfile` (PENDING) үүсгэнэ. Шинэ `PATCH /api/admin/nurses/:id/profile` (баталгаажуулах, зөвшөөрлийн №/хугацаа, ур чадвар, бүс). Хэн, хэзээ баталгаажуулсныг аудитлана.
2. wclient: сувилагчийн жагсаалтад профайл/баталгаажуулалтын талбар, `EN_ROUTE/REFUSED/INCIDENT` шошго, `REFUSED/INCIDENT`-ийг шийдэх үйлдэл (R4): дахин томилох (`PAID` руу буцаах), хаах, тайлбар.
3. R9: вэбийн хуучин сувилагчийн нэвтрэлт/Visit урсгалыг унтраах эсэхийг шийдэж, `staff start/complete`-ийг `finish` руу шилжүүлнэ. Дараа нь хуучин `complete` guard-ыг хатуу болгоно.
- **Гарах шалгуур:** админ вэбээр үүсгэсэн сувилагч баталгаажуулагдаж апп-д дуудлага авна (интеграцийн тест).

### Үе C · Захиалгын мөчлөг (M–L) · backend + `App/**` (зөвшөөрөл)
1. R5: «Хуваарьт гарахаас татгалзах» (`ASSIGNED/EN_ROUTE`, шалтгаантай) → захиалга `PAID` руу буцаж, тэр сувилагчаас бусдад дахин dispatch; сувилагчийн статистикт тооцно. «Хаалган дээрх татгалзал» (`REFUSED`) тусдаа үлдэнэ.
2. R13: хэн ч аваагүй, 15 мин → админд харагдах «томилоогүй» жагсаалт (main-ийн dashboard `attentionUnassigned`-ийг ашиглана), `EXPIRED` хугацаа.
3. R12: зөвшөөрөл дуусахыг `SUSPENDED` болгох өдөр тутмын ажил (dispatch loop-д нэмэлт), 30/7 хоногийн сануулга.
4. `App/` (үйлчлүүлэгч): `EN_ROUTE` («Сувилагч замдаа»), `REFUSED`, `INCIDENT`-ийн хүнд ойлгомжтой тайлбар. R4 буцаалтын бодлого (хуульч) гарсны дараа.
- **Гарах шалгуур:** сувилагч татгалзвал өөр сувилагчид санал очно; үйлчлүүлэгч төлөвийг ойлгомжтой харна.
